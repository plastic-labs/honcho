The short version:

- **Your data is yours.** Everything Honcho stores about a peer is readable back out through the API, and deletable. We never train public models on Customer Content without your explicit opt-in.
- **Honcho Cloud isolates each organization.** Your organization gets its own Honcho instance with its own database. Plastic Labs' control plane routes requests; it does not read your data.
- **Self-hosting is a first-class path, not a fallback.** The same open-source server runs the managed service. Run it yourself and nothing leaves your network except the LLM calls you configure, which can point at a local model.

The rest of this page is the detail behind those three lines.

## What Honcho stores

Honcho is a memory layer, so it keeps more than the messages you send it. Knowing what exists is the first step to controlling it.

| Data | What it is | Where it comes from |
|---|---|---|
| Messages | The raw content you write to a session: conversation turns, events, documents, tool traces | You, via the API, SDK, or a plugin |
| Embeddings | Vector representations of messages, used for search | Generated by Honcho from messages |
| Explicit conclusions | Facts drawn directly from messages, tied to the session they came from | The [deriver](/v3/documentation/core-concepts/reasoning), in the background |
| Derived conclusions | Deductions, inductions, and contradictions consolidated across sessions, stored at the workspace level | The deriver and [dreaming](/v3/documentation/features/advanced/dreaming) |
| Summaries | Rolling summaries of a session's history | The summarizer |
| Peer cards | A short, structured profile per peer | Generated, or set by you |
| Files | Anything uploaded with [file uploads](/v3/documentation/features/advanced/file-uploads) | You |

Two consequences worth knowing before you store anything sensitive:

1. **Conclusions are not messages.** Deleting a session removes its messages and the explicit conclusions drawn from them. Derived conclusions live at the workspace level and survive session deletion. See [Deleting Data](/v3/documentation/features/advanced/deleting-data) for how to remove them.
2. **Honcho reasons with LLMs.** Message content is sent to a language model to derive conclusions, write summaries, and answer [chat](/v3/documentation/features/chat) queries. On Honcho Cloud, that means our inference providers see it in transit. Self-hosted, you choose the model, including a local one.

## Honcho Cloud

### Where your data lives

Every organization on [app.honcho.dev](https://app.honcho.dev) gets a dedicated Honcho instance (API and background worker) with its own Postgres database. Workspaces, peers, sessions, messages, and conclusions live only in that database. The management layer that provisions instances and routes requests never reads tenant data.

Infrastructure runs on Google Cloud in the United States. Data is encrypted in transit with TLS 1.2 or higher and at rest with AES-256.

### Who can read it

- **Your API keys.** Keys scope to an admin, a workspace, a peer, or a session, and a scoped key never widens to its parent. A peer-scoped key can read only its own peer and the sessions that peer is in; a session-scoped key cannot reach peer routes at all. See [API keys](/v3/documentation/reference/platform#3-manage-api-keys).
- **Our inference providers.** Honcho sends message content to language models to reason over it. The current list of providers is in the [Privacy Policy](https://app.honcho.dev/privacy) under sub-processors. Zero-data-retention arrangements with inference providers are available for teams; contact [privacy@honcho.dev](mailto:privacy@honcho.dev).
- **Plastic Labs staff.** Production access is least-privilege, behind MFA, and logged. Staff do not read customer content in the course of operating the service. Support requests that need a look at your data happen with your permission, on the data you point us at.

### What we do with it

- We **do not** train public language models on your content. Ever, without an explicit opt-in from you.
- We **may** use de-identified data to improve the models that run Honcho itself. "De-identified" means personal information is masked before anything reaches a research dataset. This is the non-public fine-tuning described in the [Privacy Policy](https://app.honcho.dev/privacy).
- We **do not** sell data or serve ads against it.

### Deleting your data

Deletion is permanent. There is no soft delete and no trash.

- Delete a **session** and its messages, embeddings, and explicit conclusions go with it.
- Delete a **workspace** and every peer, session, message, conclusion, embedding, file, and queued task in it goes with it.
- Delete **conclusions** individually when you want a specific fact gone but the conversation kept.

[Deleting Data](/v3/documentation/features/advanced/deleting-data) covers the endpoints and the order to call them in. To close an account entirely, email [privacy@honcho.dev](mailto:privacy@honcho.dev); identity is verified and the request completes within 30 days.

### Taking your data with you

Nothing in Honcho is locked in. Messages, conclusions, summaries, representations, and peer cards all come back out through the same API that put them in, so a move from Honcho Cloud to a self-hosted instance is a read-and-write loop against two base URLs. Community members have moved tens of thousands of conclusions this way. The server is [AGPL-3.0](/v3/contributing/license), so the thing you move to is the thing you moved from.

## Self-hosting

If the honest answer to "what about my data" has to be "it never leaves," self-host. [Local Environment Setup](/v3/contributing/self-hosting) gets a full stack running with one command:

```bash
uv tool install honcho-cli
honcho start --setup
```

What you get is the same server that runs Honcho Cloud, pinned to a published image, with Postgres and Redis alongside it. Then:

- **Storage stays local.** Messages, embeddings, and conclusions live in your Postgres. Files live on your disk or the bucket you configure.
- **The only outbound traffic is inference.** Honcho calls whichever LLM provider you set in `.env`. Point it at Ollama, vLLM, or any OpenAI-compatible endpoint on your own hardware and no content leaves the network. See [Configuration](/v3/contributing/configuration#llm-configuration) for per-feature model settings.
- **Telemetry is off by default.** `TELEMETRY_ENABLED` and `SENTRY_ENABLED` both default to `false`. Nothing phones home. There is no license key and no account required.
- **Auth is yours to configure.** The compose file binds every port to `127.0.0.1`. Turn on `AUTH_USE_AUTH` before exposing the API beyond localhost.
- **Plugins work the same.** Point any integration at `HONCHO_BASE_URL=http://127.0.0.1:8000` and it writes to your instance instead of ours.

### Hosted or self-hosted

| | Honcho Cloud | Self-hosted |
|---|---|---|
| Where messages and conclusions live | Your organization's own database on our infrastructure, US | Your Postgres, wherever you run it |
| Who runs inference | Our providers, under our agreements | The provider or local model you configure |
| Encryption | TLS in transit, AES-256 at rest | Whatever your infrastructure provides |
| Deletion | API and dashboard; account deletion by email | API; or drop the database |
| Compliance paperwork | SOC 2 Type I, DPA and ZDR on request | Yours |
| Who fixes it at 3am | Us | You |

## Frequently asked

**Does Honcho train on my data?**
Not public models, and not without opt-in. De-identified data may be used to improve Honcho's own internal models. Self-hosted instances send us nothing.

**Can I see what Honcho has concluded about me?**
Yes. List a peer's conclusions, read its representation, or ask it directly through [chat](/v3/documentation/features/chat). The dashboard shows the same.

**My agent plugin sends everything I type. Is that the whole conversation?**
It depends on the integration. Most plugins write the conversation turns to a session so Honcho can learn from them. Check the plugin's own documentation for what it filters, and use session-scoped keys to bound what a plugin can reach.

**What about PII and PHI?**
Honcho does not mask or strip personal information from what you send it. If a field must never be stored, redact it before the write. Honcho is not a HIPAA-covered service.

**Is there a data residency option outside the US?**
Not on Honcho Cloud today. Self-host in the region you need.

**Where do I send security or privacy questions?**
[privacy@honcho.dev](mailto:privacy@honcho.dev) for data questions. Vulnerabilities go through [GitHub private reporting](https://github.com/plastic-labs/honcho/security/advisories/new) or [support@honcho.dev](mailto:support@honcho.dev) with `[SECURITY]` in the subject; see the [security policy](https://github.com/plastic-labs/honcho/blob/main/SECURITY.md).
